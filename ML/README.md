# Machine Learning Dataset Directory (`ML/`)

This directory serves as the destination for standardized, machine learning ready training and evaluation datasets generated by [`pipeline.py`](../pipeline.py).

> [!NOTE]
> This `README.md` file acts as a placeholder so the `ML/` folder is tracked by version control. Generated image crops, GeoPackages, and CSV tables stored here are excluded from Git via `.gitignore` as reproducible pipeline build artifacts.

---

## Output Directory Structure

When `python pipeline.py` executes, it processes all study sites discovered in `data/` and populates `ML/` with the following structure:

```
ML/
├── README.md                           # This placeholder and output specification
├── sites_metadata.csv                  # Global summary table across all processed sites
│
├── Unita/                              # Output assets for site "Unita"
│   ├── image_metadata.csv              # Crop-level metadata table
│   ├── shape_geometries.gpkg           # Vector layer of crop bounding boxes
│   ├── polygon_geometries.gpkg         # Vector layer of parent geoglyph footprints
│   ├── Unita_00001_0.png               # Positive geoglyph crop (Site_GeoID_CropID)
│   ├── Unita_00001_1.png               # Positive crop from same polygon
│   ├── ...
│   └── Unita_00045_0.png               # Negative background crop
│
├── ChugChug/                           # Output assets for site "ChugChug"
│   ├── image_metadata.csv
│   ├── shape_geometries.gpkg
│   ├── polygon_geometries.gpkg
│   └── ChugChug_*.png
│
└── Lluta/                              # Output assets for site "Lluta"
    ├── image_metadata.csv
    ├── shape_geometries.gpkg
    ├── polygon_geometries.gpkg
    └── Lluta_*.png
```

## Generated Artifacts & Specifications

### 1. Image Crops (`{SITE_NAME}_{GEO_ID}_{CROP_ID}.png`)

Square PNG image patches extracted and rescaled according to parameters in `pipeline_config.json`:
- **Dimensions**: Fixed square resolution (e.g., $224 \times 224$ pixels as set by `window_size`).
- **Spatial Resolution**: Standardized metric scale (e.g., $0.05\text{ m/px}$ as set by `target_scale`), resampled via area-weighted averaging.
- **Naming Convention**: `{SITE_NAME}_{GEO_ID}_{CROP_ID}.png`
  - `SITE_NAME`: Name of the study area (e.g. `Unita`).
  - `GEO_ID`: 5-digit zero-padded ID of the parent polygon / sampled datapoint (e.g. `00024`).
  - `CROP_ID`: Crop index within the parent datapoint (e.g. `0`, `1`, `2`...).
- **Classes**:
  - **Positive Crops (`DATA_LABEL = 1`)**: Grid-aligned crops with geoglyph polygon spatial intersection meeting `threshold_crop_content`.
  - **Negative Crops (`DATA_LABEL = 2`)**: Randomly sampled non-overlapping background terrain patches with zero geoglyph intersection and valid non-nodata pixels.

### 2. Global Site Summary: `sites_metadata.csv`

Located at `ML/sites_metadata.csv`. Contains one record per processed study site summarizing spatial dimensions, class counts, and channel intensity statistics:

| Field | Type | Description |
| :--- | :--- | :--- |
| `SITE_NAME` | `string` | Name of the study area (e.g., `Unita`, `ChugChug`). |
| `CRS` | `string` | Projected Coordinate Reference System (e.g., `EPSG:32719`). |
| `QUAD_AREA` | `float` | Total ground area of the orthomosaic in square meters. |
| `QUAD_WIDTH_PX` | `float` | Width of source orthomosaic raster in pixels. |
| `QUAD_HEIGHT_PX` | `float` | Height of source orthomosaic raster in pixels. |
| `QUAD_WIDTH_M` | `float` | Width of study area in ground meters. |
| `QUAD_HEIGHT_M` | `float` | Height of study area in ground meters. |
| `SCALE_MPX` | `float` | Native spatial resolution of source raster in meters/pixel. |
| `NUMBER_OF_LABELS` | `integer` | Total vector label geometries in source GeoPackage. |
| `NUMBER_OF_GEOGLYPHS`| `integer` | Count of positive geoglyph polygons (`class = 1`). |
| `NUMBER_OF_GROUND` | `integer` | Count of labeled ground polygons (`class = 2`). |
| `NUMBER_OF_IMAGES` | `integer` | Total generated crops for this site (Positives + Negatives). |
| `NUMBER_OF_POSITIVES`| `integer` | Total positive geoglyph crops generated. |
| `NUMBER_OF_NEGATIVES`| `integer` | Total negative background crops sampled. |
| `CHANNELS` | `integer` | Number of image channels (e.g. `3` for RGB). |
| `CHANNEL_n_MIN` | `numeric` | Minimum pixel value for channel $n$ across the orthomosaic. |
| `CHANNEL_n_MAX` | `numeric` | Maximum pixel value for channel $n$ across the orthomosaic. |
| `CHANNEL_n_AVG` | `float` | Mean pixel value for channel $n$ across the orthomosaic. |

---

### 3. Crop-Level Summary: `image_metadata.csv`

Located at `ML/<SiteName>/image_metadata.csv`. Contains one record for every PNG crop generated for that study site:

| Field | Type | Description |
| :--- | :--- | :--- |
| `SITE_NAME` | `string` | Study site identifier. |
| `ID` | `string` | Composite crop identifier (`{SITE_NAME}_{GEO_ID}_{CROP_ID}`). |
| `GEO_ID` | `string` | Parent polygon / datapoint ID (5-digit padded integer). |
| `CROP_ID` | `string` | Crop index (5-digit padded integer, e.g. `00000`). |
| `DATA_LABEL` | `integer` | Numerical class label: `1` = Geoglyph (Positive), `2` = Ground (Negative). |
| `SCALE_MPX` | `float` | Standardized resolution in meters per pixel (e.g. `0.05`). |
| `CENTER_X` | `float` | Centroid X coordinate in CRS units (e.g. UTM Easting). |
| `CENTER_Y` | `float` | Centroid Y coordinate in CRS units (e.g. UTM Northing). |
| `AREA` | `float` | Crop ground footprint area in square meters. |
| `CHANNELS` | `integer` | Number of color/spectral channels. |
| `CRS` | `string` | Coordinate Reference System of the crop bounds. |
| `THRESHOLD_CLEAR` | `float` | Fraction of geoglyph area within the crop window ($1.0$ for negative samples). |

---

### 4. Vector Layers: `shape_geometries.gpkg` & `polygon_geometries.gpkg`

Located in each `ML/<SiteName>/` directory:
- **`shape_geometries.gpkg`**: Spatial GeoPackage containing the bounding box polygons for every extracted crop. Allows spatial visualization and inspection of crop coverage in GIS software (QGIS/ArcGIS).
- **`polygon_geometries.gpkg`**: Spatial GeoPackage containing the original vector boundaries of the parent geoglyph polygons (`GEO_ID`), preserving ground-truth archaeological outlines.

## How to Generate Outputs

To generate or refresh the dataset in this directory:

1. Place raw site data into `data/<SiteName>/`.
2. Configure parameters in `pipeline_config.json` (such as `target_scale`, `window_size`, `stride`, `threshold_crop_content`, and `negatives_ratio`).
3. Run the pipeline from project root:
   ```bash
   python pipeline.py
   ```
